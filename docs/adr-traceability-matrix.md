# ADR 可追踪矩阵

Source of truth: frozen ADR Baseline v0.4 from `AGENTS.md` and `docs/adr/*.md`。

本文档把 accepted ADR 追踪到受影响模块、canonical events、状态对象、规格文档和 replay/eval 要求。它不创建新事件名，也不替代 ADR。

## Implementation Readiness 取值

- `ready`: ADR 决策可直接按当前 baseline 与 derived specs 实现。
- `needs_event_schema`: 需要 `docs/specs/event-registry.md` 中的 canonical payload fields。
- `needs_state_reducer`: 需要 `docs/specs/state-reducers.md` 中的 reducer semantics。
- `needs_replay_fixture`: 需要 replay scenario / fixture definition。
- `needs_eval_case`: 需要 deterministic replay 之外的 evaluation case。
- `needs_adapter_contract`: 需要 adapter capability / degradation contract。
- `needs_open_decision`: 实现前需要 future ADR 或 explicit ADR update。

## Canonical Name Mapping Notes

Frozen ADR canonical registry 使用 `SEMANTIC_COMMITMENT_EMITTED` 和 `SPOKEN_PLAN_EMITTED`。如果 implementation 或外部文档希望把 `SEMANTIC_COMMITMENT_CREATED` 或 `SPOKEN_PLAN_CREATED` 作为 journal event name，必须先更新 ADR-002。本文 matrix 中这些 label 只映射到 canonical emitted events，不是新事件名。[ADR-002]

同理，`STALE_TOOL_RESULT_RECORDED` 映射到 canonical chain：

```text
TOOL_RESULT_RECEIVED
  -> TOOL_RESULT_MARKED_STALE
  -> STALE_EVIDENCE_RECORDED
```

任何 MVP-relevant 新事件名前，都必须先更新 ADR-002 和 `docs/specs/event-registry.md`。[ADR-002, ADR-004, ADR-015]
