# ADR Traceability Matrix

Source of truth: frozen ADR Baseline v0.4 from `AGENTS.md` and `docs/adr/*.md`.

Implementation readiness values:

- `ready`: ADR decision is directly implementable from this baseline and the derived specs in this folder.
- `needs_event_schema`: requires canonical payload fields from `docs/specs/event-registry.md`.
- `needs_state_reducer`: requires reducer semantics from `docs/specs/state-reducers.md`.
- `needs_replay_fixture`: requires replay scenario/fixture definition.
- `needs_eval_case`: requires evaluation case beyond deterministic replay.
- `needs_adapter_contract`: requires adapter capability/degradation contract.
- `needs_open_decision`: requires a future ADR or explicit ADR update before implementation.

## Canonical Name Mapping Notes

The frozen ADR canonical registry uses `SEMANTIC_COMMITMENT_EMITTED` and `SPOKEN_PLAN_EMITTED`. If an implementation or external document wants `SEMANTIC_COMMITMENT_CREATED` or `SPOKEN_PLAN_CREATED` as journal event names, ADR-002 must be updated first. In this traceability matrix, those labels map to the canonical emitted events and are not new event names. [ADR-002]

Similarly, `STALE_TOOL_RESULT_RECORDED` maps to the canonical chain `TOOL_RESULT_RECEIVED` -> `TOOL_RESULT_MARKED_STALE` -> `STALE_EVIDENCE_RECORDED`. [ADR-002, ADR-004]
